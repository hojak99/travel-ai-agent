# 04. Compaction

대화가 길어지면 모든 메시지를 계속 LLM에 전달할 수 없다. Compaction은 오래된 대화를 요약하되 이후 의사결정에 필요한 사실을 보존하는 과정이다. 원본 07·08장의 핵심처럼 한 번의 전체 요약이 아니라 압력 수준에 따른 패밀리로 설계한다.

```text
정상 → 경고 → Microcompact → Full Compact → 실행 차단
```

- `Microcompact`: 오래된 대용량 Tool 결과를 출처·핵심 사실만 남기고 대체한다.
- `Full Compact`: 오래된 대화의 의사결정과 미해결 항목을 요약한다.
- 재구성: 구조화 State, 요약, 최근 원문, 진행 중인 Tool/승인 상태를 다시 조립한다.

## 보존할 정보

```text
목적지와 날짜, 여행자 수, 예산과 통화
선호와 제외 조건, 확정 일정, 미해결 질문
검색 결과의 출처와 조회 시각
사용자가 거절한 선택, 승인 대기 인자, 실패한 Tool과 재시도 횟수
```

요약문과 `TravelConstraints`를 함께 저장한다. 요약은 표현용이고 구조화 상태는 검증과 Tool 호출용이다.

## 직접 구현 과제

- 메시지 수 또는 예상 토큰 수 기준을 정한다.
- 임계치를 넘으면 `CompactionService`를 호출한다.
- 목적지, 날짜, 예산, 확정 일정 보존 테스트를 작성한다.
- 최근 메시지는 원문으로 남긴다.
- 입력 토큰뿐 아니라 다음 Decision과 Tool 호출을 위한 출력 예약 공간을 남긴다.
- 연속 Compaction 실패 횟수를 저장하고 무한 압축 Loop를 차단한다.

## 손실 허용 기준

중복 표현과 오래된 Tool 원문은 잃어도 되지만, 아래 항목은 잃으면 안 된다.

- 사용자가 직접 제공한 제약과 확정·거절한 결정
- 출처 URL, 조회 시각, 가격의 통화·조건
- 현재 Workflow 단계와 승인 상태
- 아직 답하지 않은 질문

## 학습 실험과 완료 기준

- 압축 전후 같은 질문에 대해 핵심 제약이 유지되는지 golden test로 비교한다.
- 100KB Tool 결과를 넣어 Microcompact가 먼저 작동하는지 검증한다.
- 요약 모델 실패를 반복시켜 서킷 브레이커가 Loop를 종료하는지 확인한다.
- 압축 후 Prompt를 재생해 Tool call/result 순서가 깨지지 않으면 완료다.
